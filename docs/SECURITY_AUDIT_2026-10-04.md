# Аудит безопасности SketchForge — 2026-10-04

- Что проверялось: коммит `e9cb8e8` (совпадает с `main` оригинала `Formsmith746/SketchForge-3D` на эту дату). Номера строк — по этому коммиту.
- Как: чтение кода, конфигов, `package-lock.json`, `node_modules` и истории git. Приложение не запускалось, сетевой трафик не снимался, атаки не воспроизводились.
- Вопросы: (1) отправляет ли проект данные пользователя наружу; (2) не вредоносна ли десктоп-версия.

## Вердикт

**Данные.** Модели, файлы и проекты третьим лицам не отправляются. Аналитики, телеметрии, сбора отпечатков браузера, внешних скриптов, шрифтов и CDN в коде нет. Наружу ходит только проверка обновлений на GitHub автора (Formsmith746): уходят IP и User-Agent, содержимое проектов — нет. Побочные каналы:
- Next.js (фреймворк, не проект) шлёт анонимную статистику в Vercel при `npm run dev/build/start`.
- PNG-превью проектов загружаются на сервер, с которого открыто приложение: локально — свой диск, в Docker — диск сервера.

**Десктоп.** Признаков вредоносного кода нет: нет автозапуска при входе, скрытых процессов (кроме своего веб-сервера на `127.0.0.1:62158`), перехвата клавиатуры, загрузки кода из сети в обход автообновления. Настройки окна Electron правильные. Оговорки:
- обновления берутся из релизов автора, а не из форка; сборки под Windows и Linux не подписаны;
- локальный сервер без пароля умеет записать файл в любую папку.

## Реальный риск

### 1. Высокий — только `npm run dev` / `npm start` (десктоп и Docker не затронуты)

Любой в той же Wi-Fi / локальной сети может записать любой файл на диск, а через это выполнить свой код.

- Где: `apps/web/src/app/api/local-download/route.ts:16-36, 80-88`, `package.json:16,21`.
- Почему:
  - `next dev` и `next start` без `-H` слушают все сетевые интерфейсы.
  - Без `-H` Next собирает адрес запроса как `http://localhost:<port>/...`, кто бы ни подключился (`node_modules/next/dist/server/lib/router-utils/resolve-routes.js:105`, `opts.hostname || 'localhost'`). Проверка «только localhost» смотрит на этот адрес.
  - Запрос без заголовков `Origin` и `Sec-Fetch-Site` (так шлёт curl) проверку проходит.
  - Папку и имя файла задаёт отправитель, абсолютный путь разрешён. Ответ содержит полный путь — раскрывает домашнюю папку.
- Чем грозит: записать `apps/web/src/app/api/x/route.ts` — dev-сервер скомпилирует его при первом обращении и выполнит от имени пользователя; или положить файл в `~/Library/LaunchAgents` — запустится при входе в систему.
- Тем же путём из сети доступен `/api/sketchforge-mcp` (`sketchforge-mcp/route.ts:16-46`): прочитать открытую сцену, снять картинку вьюпорта, удалить или изменить объекты.
- Что сделать:
  - прописать `-H 127.0.0.1` в скрипты `dev` и `start` (или `npm run dev -- -H 127.0.0.1`);
  - в роуте отклонять запрос без `Origin` или без `sec-fetch-site: same-origin`; ограничить запись одной папкой;
  - включённый файрвол macOS тоже закрывает доступ из сети.

### 2. Средний — `npm run dev` / `npm start` из git-клона: самообновление тянет код автора

- Где: `apps/web/src/app/api/app-update/route.ts:15, 159-194, 201-232`, `scripts/restart-local-dev.mjs`.
- `POST /api/app-update`:
  1. `git fetch https://github.com/Formsmith746/SketchForge-3D.git main`;
  2. `git merge --ff-only FETCH_HEAD` в текущую ветку;
  3. `npm install` (выполняет установочные скрипты пакетов);
  4. перезапуск `npm run dev` отдельным фоновым процессом.
- Срабатывает, если у автора версия новее и в отслеживаемых файлах нет незакоммиченных правок.
- Кто может запустить: пользователь кнопкой; любой из локальной сети (как в п.1); сайт через DNS-rebinding (домен сайта начинает указывать на 127.0.0.1, `Origin` сравнивается с `Host`, который при этом контролирует атакующий). Chrome частично закрывает это запросом доступа к локальной сети, Firefox и Safari — нет.
- Атакующий не выбирает код: это всегда `main` автора. Риск — доверие к аккаунту Formsmith746 и неожиданный merge в свою ветку.
- Что сделать: удалить локальный апдейтер (`runLocalUpdate`) или направить `OFFICIAL_REPO_URL` и `DEFAULT_MANIFEST_URL` на свой форк; плюс `-H 127.0.0.1`.

### 3. Средний — десктоп, собранный из форка: автообновление смотрит в релизы Formsmith746

- Где: `apps/desktop/electron-builder.yml:8-12`, `apps/desktop/main.cjs:206-254`.
- Через 4 с после старта и затем каждые 6 ч приложение проверяет `github.com/Formsmith746/SketchForge-3D/releases`. Если там версия новее, кнопка «Update» скачает и поставит бинарник автора поверх своей сборки. Без клика ничего не ставится (`autoDownload=false`, `autoInstallOnAppQuit=false`).
- Проверка подлинности:
  - Windows: сборки в CI не подписываются, electron-updater подпись не проверяет (`node_modules/electron-updater/out/NsisUpdater.js:84-90`: нет имени издателя — проверка пропускается);
  - Linux AppImage: только хэш из манифеста того же релиза;
  - macOS: для неподписанных релизов манифест не публикуется, автообновление не работает.
- Что сделать: `owner` → свой аккаунт, либо убрать `publish` и вызов `setupDesktopUpdater()`. Для своих сборок — подпись кода и `publisherName`.
- То же в веб-режиме: `GET /api/app-update` (`route.ts:14, 100-121`) при каждом открытии дашборда (`page.tsx:1596`, кэш 5 мин) запрашивает `raw.githubusercontent.com/Formsmith746/.../package.json` — автор видит IP и факт запуска. Переопределяется `SKETCHFORGE_UPDATE_MANIFEST_URL`.

### 4. Низкий — десктоп на машине с несколькими пользователями

- Локальный сервер `127.0.0.1:62158` без авторизации (`main.cjs:11, 67-82`): любая программа или другой пользователь машины может без `Origin` записать файл куда угодно с правами владельца приложения.
- Сайты в браузере этого не могут: `Origin` сверяется с `127.0.0.1:62158`, DNS-rebinding не проходит.
- На Mac с одним пользователем новых возможностей не даёт: локальный вредонос и так пишет файлы.
- Что сделать: случайный токен на запуск (main передаёт окну, API требует) или сохранение через IPC с системным диалогом.

### 5. Низкий — Docker на сервере: API общих проектов без авторизации

- Любой, кто достучится до порта 3000/80, может читать, перезаписывать и удалять общие `.skf`; ETag для удаления отдаётся в списке.
- `POST /api/project-thumbnail` не ограничен по количеству — можно забить диск файлами по 5 МБ.
- Для класса в локальной сети это по задумке. В интернет — только за прокси с паролем.

### 6. Для сведения — телеметрия Next.js

Скрипты `dev/build/start` не выставляют `NEXT_TELEMETRY_DISABLED`. Десктоп-сборка и Docker её отключают. Отключить локально: `npx next telemetry disable`.

## Теоретическое и укрепление

- Electron, сделано хорошо: `contextIsolation` и `sandbox` включены, `nodeIntegration=false` (`main.cjs:299-304`); мост к странице — 3 функции (версия, проверить обновление, поставить обновление); переходы и `window.open` ограничены своим адресом, внешние ссылки — в системный браузер и только http/https (`main.cjs:309-333`); нет автозапуска, глобальных горячих клавиш, доступа к буферу обмена и захвата экрана в main-процессе.
- Electron, не хватает: обработчика разрешений (по умолчанию камера, микрофон, геолокация выдаются без вопроса; грузится только своя страница, риск мал); CSP; проверки отправителя IPC; Electron fuses (`RunAsNode` отключить нельзя — приложение запускает им свой сервер).
- Закрытие окна прячет его в трей: сервер и проверка обновлений работают до «Quit» в трее (`main.cjs:339-343, 398-401`).
- Если порт 62158 занят чужим процессом, окно может загрузить чужую страницу (`waitForServer` принимает любой ответ 2xx–4xx); ей доступны только функции обновления.
- Десктоп пишет превью внутрь папки установки (`Resources/web/apps/web/.codex/project-thumbnails`, `project-thumbnail/route.ts:7`); на macOS это меняет содержимое `.app`.
- `apps/web/public/assets/occt/occt-wasm.wasm` (22 МБ) — старая версия, кодом не загружается (берётся `/occt/` из `node_modules`), но попадает в сборки. Лучше удалить.
- GitHub Actions: если включить в форке, `docker.yml` при push в `main` публикует образ в ghcr.io под своим аккаунтом; `sanity-content-deploy` без секретов Cloudflare ничего не сделает.

Установочные скрипты только у `sharp` (проверка libvips), `electron-winstaller` (копирует 7z под архитектуру), `fsevents` — известные пакеты.
